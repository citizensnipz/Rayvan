# Rayvan EMC native runtime

Native C++20 implementation of the EMC core with both the original request-routed N1/N2 path and an experimental routing-free heterogeneous N1 collective. It uses LibTorch/ATen for tensors, autograd, CUDA, cuBLAS/cuDNN-backed operators, AdamW, and serialization. The runtime does not embed or invoke Python.

## Supported architecture

- one configurable N2 request-routing event;
- an isolated routing-free mode with shared causal GQA/RoPE, independent low-rank expert activations, sparse chunk execution, and persistent latent attention;
- variable ordered populations of independent GPT, SSM, recurrent/GRU, and Delta N1 nodes;
- configurable N1 depth and N2 top-K;
- sparse GPU-resident assignment metadata and inverse dispatch;
- chunk-local GPT causal attention, exact diagonal SSM scan, and LibTorch GRU;
- a CUDA-native gated-Delta recurrence with custom backward, FP32 state, bounded recomputation scratch, and BF16 vectors;
- proposal-attention Integrator and tied embedding/output weights;
- FP32 and CUDA BF16 autocast;
- native foreach AdamW training, accumulation, clipping, evaluation, token budgets, and milestone retention;
- deterministic pretokenized streams with split identity and fingerprint;
- native model/optimizer checkpoints with model-only evaluation loading;
- routing, Integrator, norm, RSS, and CUDA allocator diagnostics;
- disable/next-best replacement, forced alternate routing, and zero-proposal interventions.

Explicitly unsupported: N3/N4, distributed/network execution, Vulkan, a Rust FFI implementation, and tokenizer implementation. GPT-2 tokenization remains an external preprocessing step producing `.rvtok` files. The Delta CUDA kernel supports head dimensions through 64 and chunk sizes 16, 32, and 64.

## Dependencies

- CMake 3.25 or newer;
- a C++20-capable MSVC toolset;
- LibTorch built for the desired CUDA version;
- NVIDIA driver compatible with that LibTorch build.

No test framework, JSON library, tokenizer library, Python runtime, Triton, or FLA runtime is linked into `rayvan_emc`. CUDA-enabled builds require the CUDA toolkit in addition to CUDA LibTorch.

## Windows + CUDA build

Use either the LibTorch C++ distribution or the CUDA-enabled Python wheel's CMake package, but keep the exact Torch release and CUDA target identical to the Python reference. Never point a CUDA build at a CPU-only wheel. The validated environment is PyTorch/LibTorch 2.13.0+cu130 with the CUDA 13.0 toolkit.

From an x64 Native Tools for Visual Studio PowerShell, the following resolves Torch from the active Python environment without a user-specific path. Ninja avoids depending on Visual Studio's optional CUDA integration:

```powershell
$TorchPrefix = python -c "import torch; print(torch.utils.cmake_prefix_path)"
$Nvcc = (Get-Command nvcc).Source
cmake -S cpp -B build/emc -G Ninja `
  -DCMAKE_BUILD_TYPE=Release `
  -DCMAKE_PREFIX_PATH="$TorchPrefix" `
  -DCMAKE_CUDA_COMPILER="$Nvcc"
cmake --build build/emc --parallel
ctest --test-dir build/emc --output-on-failure
build/emc/rayvan-emc-smoke.exe --cuda
```

Adjust the CUDA toolkit path to the version matching LibTorch. A Visual Studio 2022 generator (`-G "Visual Studio 17 2022" -A x64`) also works when NVIDIA's Visual Studio CUDA build customization is installed; otherwise CMake reports `No CUDA toolset found`.

At runtime, place LibTorch DLLs on `PATH`:

```powershell
$TorchLib = python -c "import pathlib,torch; print(pathlib.Path(torch.__file__).parent / 'lib')"
$env:PATH = "$TorchLib;$env:PATH"
```

CPU-only development can use the CMake package shipped with a Python Torch installation, but that is not the deliverable CUDA runtime:

```powershell
$TorchPrefix = python -c "import torch; print(torch.utils.cmake_prefix_path)"
cmake -S cpp -B build/emc-cpu -DCMAKE_PREFIX_PATH="$TorchPrefix"
cmake --build build/emc-cpu --config Release --parallel
```

## Reference fixtures and parity

Fixtures in `tests/fixtures/reference` are generated by the unchanged mathematical Python implementation and the mixed N2 population (`GPT, SSM, recurrent, Delta`):

```powershell
$env:PYTHONPATH = "emc"
python cpp/python/export_reference.py cpp/tests/fixtures/reference
ctest --test-dir build/emc -C Release --output-on-failure
```

The 38 native cases cover construction, every N1, independent Delta recurrence checks, FP32/BF16 CUDA forward and gradient parity, allocation refusal, mixed Python/C++ routing and training parity, legacy and routing-free checkpoints, causal interventions, sparse dispatch, shared GQA/RoPE causality and fused-backend parity, routing-free balancing/state behavior, Integrator gradients, tying, AdamW state parity, and trainer resume/telemetry.

Reference tolerances are FP32 `atol=2e-5, rtol=2e-4` for ordinary tensors, relaxed to at most `atol=8e-5, rtol=8e-4` for accumulated gradients. BF16 sanity uses `atol=3e-2, rtol=5e-2`. Top-K IDs are exact. A mismatch is an error; genuine cutoff score ties must be diagnosed from saved router scores rather than silently accepted.

Export an already-tokenized TinyStories train/validation tensor without reimplementing GPT-2 BPE:

```powershell
python cpp/python/export_token_stream.py train_tokens.pt train.rvtok `
  --split-id "tinystories/<dataset-revision>/train"
python cpp/python/export_token_stream.py validation_tokens.pt validation.rvtok `
  --split-id "tinystories/<dataset-revision>/validation"
```

The native loader verifies token count, split identity, and FNV-1a-64 fingerprint before sampling.

## Runtime use

```cpp
rayvan::emc::ModelConfig config;
config.population = {
    rayvan::emc::N1Family::gpt,
    rayvan::emc::N1Family::ssm,
    rayvan::emc::N1Family::recurrent,
    rayvan::emc::N1Family::delta};
config.top_k = 2;

rayvan::emc::EMCModel model(config);
model.to(torch::Device(torch::kCUDA, 0));
model.eval();
rayvan::emc::InferenceScope inference;
auto result = model.forward({token_ids, true});
```

## Benchmark policy

Use identical weights and token batches. Warm runtimes, synchronize CUDA around timed regions, and report forward, forward/backward, optimizer, tokens/s, RSS, allocator allocated/reserved/peak, and checkpoint-load peak. `rayvan-emc-delta-benchmark` profiles chunk sizes and the full mixed research shape with CUDA events and CUPTI launch counts.

LibTorch and Python PyTorch use the same ATen/CUDA kernels and caching allocator. Native C++ can reduce interpreter/dispatch orchestration, make object lifetime explicit, and prevent optimizer loading during evaluation; it is not expected to make the underlying GPU kernels or allocator intrinsically smaller. Production adoption must be based on measured results from the CUDA build, not that expectation.

Run the short non-Delta scale check with `--realistic --warmup 3 --iterations 10`. `rayvan-emc-optimizer-profile` uses CUPTI callbacks and CUDA events to measure one warmed stock or foreach optimizer step; add the toolkit CUPTI `lib64` directory to `PATH` before running it.

From the repository root:

```powershell
cpp/tools/report_environment.ps1 -Python (Get-Command python).Source `
  -BuildDirectory build/emc
build/emc/rayvan-emc-smoke.exe --cuda
```

This reports Python/PyTorch, its CUDA runtime and cuDNN, the resolved native `Torch_DIR`, local toolkit/compiler, NVIDIA driver/GPU, compile-time LibTorch version, CUDA availability, compute capability, and a BF16 matmul smoke result.
